# Справочник общесистемных UX-паттернов

Соответствует приложению: `0.9.4-beta`

Справочник дополняет обязательные правила интерфейса и предотвращает расхождение одинаковых механик на разных экранах.

## Подсказки ввода

- Чат предлагает до пяти типовых запросов с учетом этапа: создание, вопрос, добавление условия или спор.
- Для найма используются предметные вопросы и условия, для остальных договоров — универсальные.
- После начала ввода остаются только подсказки, содержащие введенные слова.
- `Arrow Up` и `Arrow Down` перемещают выделение, `Enter` или `Tab` выбирает вариант, `Escape` закрывает список.
- На смартфоне вариант выбирается одним тапом; список не блокирует прокрутку ленты.

## Поиск договоров

- Поиск работает по названию, контрагенту и статусу.
- Подсказки содержат только договоры текущего пользователя.
- Глобальные email, чужие договоры и запросы других пользователей никогда не используются.
- Выбор результата сразу открывает договор и закрывает боковую панель.

## Формы

- Одинаковые поля используют единые формулировки из `FORM_HINTS`.
- Стандартное автозаполнение браузера включено для ФИО, организации, телефона и email.
- Паспорт не сохраняется в истории подсказок и использует `autocomplete="off"`.
- Незавершенные реквизиты подписи сохраняются только в `sessionStorage` текущей вкладки, восстанавливаются после выгрузки вкладки и удаляются после успешной подписи.
- Placeholder показывает формат, но не заменяет подпись поля и сообщение об ошибке.

## Чат

- Сообщения идут одной хронологической лентой: сервис слева, пользователь справа.
- После генерации нет постоянной панели команд: вопрос, просьба изменить договор и переход к согласованию распознаются по обычному тексту пользователя.
- Кнопки применяются только для однозначных юридически значимых действий и структурированных форм, где свободный текст повышает риск ошибки.
- Формы и следующий шаг появляются только после последнего сообщения.
- Любое действие получает подтверждение в том же контексте.
- Генерация полного договора анимируется только для первой версии; точечные изменения показываются без повторного вывода договора.

## Жесты и слои

- Свайп справа налево закрывает боковую панель и модальные слои.
- Свайп слева направо возвращает на предыдущий экран только при начале от левого края.
- Нижние 96 px экрана зарезервированы для системных жестов смартфона и никогда не запускают навигацию сервиса.
- Тап вне слоя закрывает его.
- Модальное окно не отключает прокрутку собственного содержимого.
- На iOS и Android учитываются safe area и фиксированная полезная область.
- При `visibilitychange` и `pagehide` активный договор сохраняется отдельным навигационным снимком и восстанавливается после возврата.

## Реализация

Тексты и правила подсказок находятся в `frontend/src/catalogs/suggestions.js`. Новая форма или режим чата сначала добавляется в каталог, затем подключается к компоненту. Локальные массивы подсказок внутри экранов не допускаются.

## Сообщение об ошибке

- Кнопка «Сообщить о проблеме» открывает письмо на `ai-arbitr@ya.ru`.
- В письмо автоматически включаются версия, модель, этап процесса, ID договора, тип устройства, размер окна и время.
- Пользователь добавляет описание и при необходимости прикладывает скриншот.
- Текст договора, реквизиты и секретный токен гостевой ссылки в диагностику не включаются.
