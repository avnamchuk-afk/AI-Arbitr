# Общесистемные правила AI-Arbitr

Этот документ фиксирует обязательные правила поведения интерфейса. Новые функции и исправления проверяются на соответствие этим правилам до выпуска.

## 1. Диалог и последовательность

1. Основной интерфейс работает как единая хронологическая лента диалога.
2. Новая реплика, вопрос, форма и результат действия появляются только внизу ленты.
3. После каждого действия пользователь получает видимую обратную связь рядом с местом действия.
4. Следующий шаг предлагается только после завершения текущего.
5. При появлении нового шага экран прокручивается к нему автоматически, но пользователь может вернуться к истории.
6. Договор не выводится повторно после вопроса или точечного изменения; показывается только ответ или новая норма.

## 2. Мобильная навигация

1. Приоритетный интерфейс — смартфон с сенсорным управлением.
2. Свайп справа налево закрывает боковую панель или верхнее модальное окно.
3. Свайп слева направо выполняет привычное действие «Назад».
4. Тап вне панели закрывает ее.
5. Открытая панель не должна блокировать прокрутку своего содержимого.
6. Основной экран не двигается за пределы полезной области и учитывает safe area iOS.

## 3. Формы и ввод

1. Поля располагаются в порядке клиентского пути, сверху вниз.
2. При открытии формы фокус переходит в первое незаполненное поле.
3. Email контрагента подсказывается только из договоров текущего пользователя; глобальный список пользователей не раскрывается.
4. Для ФИО, телефона, email, организации и налоговых реквизитов используется безопасное автозаполнение браузера.
5. Паспортные данные не сохраняются для автозаполнения, пока Политика предусматривает эфемерную обработку.
6. Предзаполненные игровые данные явно обозначаются как примерные. Формулировка шага: «Проверьте реквизиты и при необходимости исправьте. Все верно?»
7. Ошибка показывается рядом с формой и объясняет, что исправить.
8. Подсказки чата зависят от текущего этапа и фильтруются по мере ввода, как в привычном веб-поиске.
9. Поиск договоров предлагает только записи текущего пользователя и никогда не раскрывает глобальную историю запросов.
10. Подсказки доступны с клавиатуры и касанием; выбор не отправляет сообщение автоматически, а подставляет текст для проверки.
11. Одинаковые поля и действия используют формулировки из общего справочника, а не локальные тексты экрана.

## 4. Состояние и восстановление

1. Обновление страницы возвращает пользователя в открытый договор и текущий этап.
2. Авторизация, переход по email и возврат из внешней страницы не обрывают незавершенное действие.
3. Перед внешним переходом сохраняются ID договора и минимальные данные следующего шага.
4. Повторное действие должно быть идемпотентным и не создавать лишние версии, подписи или письма.

## 5. Доверие и безопасность

1. Интерфейс не раскрывает существование чужого аккаунта, email или договора.
2. Полные реквизиты не используются для подсказок без отдельного законного механизма хранения и согласия.
3. Технические роли участников не показываются пользователю; используются юридические роли по договору.
4. Любое необратимое действие требует ясного результата и сохраняется в истории событий.

## 6. Критерий готовности

Функция не считается готовой, если на мобильном экране следующий шаг появляется выше текущего, действие не получает обратной связи, жест закрытия не работает или после обновления теряется контекст.
